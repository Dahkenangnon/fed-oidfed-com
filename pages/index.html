§02 Topologies

Six federations, each with a different shape.

The same `@oidfed` packages compose into six structurally distinct federations. Click any Trust Anchor URL — it opens directly in explore.oidfed.com with the full trust chain rendered.

single-anchor 01

1 Trust Anchor, 1 OP, 2 RPs — one configured for automatic registration, one for explicit. The minimal complete federation.

single.fed.oidfed.com →
hierarchical 02

TA → 2 Intermediates (edu, health) → leaf OP + RP under each branch. Exercises multi-step trust chains and per-branch policy.

ta.hier.fed.oidfed.com →
multi-anchor 03

2 Trust Anchors (gov, industry) above a shared Intermediate. Tests trust-anchor intersection between RP and OP.

ta-gov.multi.fed.oidfed.com →
cross-federation 04

Two independent federations bridged by a dual-anchor entity that lists both TAs in its authority hints.

ta-x.xfed.fed.oidfed.com →
constrained 05

TA with max_path_length=0: direct subordinates resolve, deeper chains are rejected by design.

ta.constr.fed.oidfed.com →
policy-operators 06

IA exercising every metadata policy operator — subset_of, value, add, and essential.

ta.policy.fed.oidfed.com →
§03 How to test

Two ways in.

Pick the surface that matches your workflow. Both target the live deployment at *.fed.oidfed.com.

Visual · Browser

explore.oidfed.com

Paste any entity URL — Trust Anchor, Intermediate, OP, or RP — and the Explorer renders the entity configuration, trust chain, resolved metadata, and any active trust marks. No install, runs in the browser.

explore.oidfed.com
Terminal · Scriptable

@oidfed/cli

Resolve trust chains, decode entity statements, verify signatures, and run spec-grade validations from the command line. Suitable for CI checks, audits, and ad-hoc debugging.

$ npm i -g @oidfed/cli
$ oidfed resolve https://single.fed.oidfed.com
✓Entity Configuration fetched
✓Trust chain assembled (3 statements)
✓Metadata policy applied
# trust_anchor: ta.single.fed.oidfed.com
npm install -g @oidfed/cli
§03.1 Or just curl

If you only need the signed Entity Configuration JWT, every entity exposes /.well-known/openid-federation:

$ curl -sS https://single.fed.oidfed.com/.well-known/openid-federation | cut -d. -f2 | base64 -d | jq .iss
"https://ta.single.fed.oidfed.com"
§04 Source

Run your own copy.

This site describes the deployment, but every line that runs it is open source. Read it, fork it, run it locally, or stand up your own federation against your own infrastructure.
